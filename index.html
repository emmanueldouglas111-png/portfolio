✓ Secure front-end principles I build by

    
    
      
  • Treat all input as untrusted. Render user-provided text with textContent, not innerHTML, to avoid cross-site scripting (XSS).
    • 
      
  • Keep secrets off the client. API keys never go in front-end code; they belong in server-side environment variables.
    • 
      
  • Ship over HTTPS. Hosting on platforms like Vercel serves sites over HTTPS by default.
    • 
      
  • Least privilege and minimal dependencies. Fewer third-party scripts means a smaller attack surface.
    •

Great Nigerian Food. One Conversation Away.

      

    

    

      
A responsive restaurant website with an AI voice-assistant concept. I recreated it from a screen recording, matching its green-and-gold look, serif headings, filterable menu and live-conversation panel.

      
What it includes

      
    
        
  • Sticky navigation with active-section highlighting and smooth scrolling
    • 
        
  • Hero section with calls to action and key stats
    • 
        
  • Menu grid with category filters, spice and bestseller tags, and photo fallbacks
    • 
        
  • "Try It Yourself" prompt cards that drive a scripted live-transcript demo
    • 
        
  • Mobile-friendly layout and keyboard focus styles
    • 
      

      
Built with

      
  • HTML5
  • CSS3
  • Vanilla JavaScript
  • Google Fonts
  • Git & GitHub
  • Vercel

      
Security notes. The chat transcript renders text with textContent, the page contains no API keys, and the demo replies are scripted, so no user data leaves the browser.
